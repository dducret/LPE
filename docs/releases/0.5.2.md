# LPE 0.5.2

`0.5.2` establishes `0.5.2-sql` as a fresh PostgreSQL baseline for the
Outlook MAPI over HTTP interoperability campaign.

## Database policy

- Every `0.5.2` deployment uses an empty database initialized from
  `crates/lpe-storage/sql/schema.sql` by
  `installation/debian-trixie/init-schema.sh`.
- The canonical schema version is exactly `0.5.2-sql`.
- There is no in-place upgrade or migration path to `0.5.2`. `update-lpe.sh`
  accepts only an already initialized `0.5.2-sql` database and refuses every
  other schema label before it stops LPE or changes data.
- An operator rebuilding a test deployment must explicitly use
  `LPE_RESET_SCHEMA=true` after taking any required backup. That action is
  destructive.

## Outlook validation

- The fresh baseline persists one MAPI store replica identity and allocates
  globally unique MAPI identity counters across the database, including each
  mailbox's default folders. This follows [MS-OXCSTOR] section 3.2.3 and the
  global-ID model in [MS-OXCFXICS].
- Final cached-mode acceptance uses a fresh `0.5.2-sql` database and a clean
  Outlook profile/OST, then verifies Mail, Calendar, Contacts,
  synchronization, notifications, and reopen after Outlook and server
  restarts.

The historical `0.5.0` and `0.5.1` release policies remain recorded in
`docs/releases/`.
